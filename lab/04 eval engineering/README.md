# eval engineering — как понять, стало ли лучше

Измерение качества модели — отдельная инженерия: набор примеров, схема прогона,
интервалы, судьи и гейты. Здесь про то, почему «accuracy выросла на 2 пункта»
чаще всего ничего не значит и что нужно, чтобы значило.

Модель нужна настоящая (в отличие от `03 context engineering/`, где цикл
проверяется на scripted-модели): оценивать нечего, пока нечего генерировать.
Общие замеры — `lab/common.py`.

Номера нумеруются внутри папки: `01`, `02`, …

Запуск — из корня репозитория:

```bash
source ./vllm-env/bin/activate
python "lab/04 eval engineering/01_accuracy_and_noise.py"
```

## Эксперименты

| Файл | О чём | Ключевой вывод |
| --- | --- | --- |
| `01_accuracy_and_noise.py` | accuracy как оценка: greedy vs sampling, детерминизм, Wilson CI, MDE, размер набора | на 16 примерах ±22 п.п.: дельта меньше — шум; схема прогона даёт сдвиг больше, чем многие «улучшения» |

## Как это складывается

```
01  базовая оценка: набор, схема прогона, интервал, минимально различимая дельта
     │
     ├── pass@k: сколько попыток считать и как оценивать «хоть раз получилось»
     ├── судья: когда эталона нет — оценка логитами меток или LLM-judge
     └── гейт: A/B на фиксированном наборе, парные прогоны, порог в CI
```

Связь с остальными папками:

- `inference/16_structured_decoding.py` и
  `inference/17_tool_reasoning_parsing.py` дают то, что здесь измеряется с другой стороны:
  validity rate вывода, а не «правильность ответа».
- `inference/22_verbalizer_classification.py` — готовый судья по
  логитам меток: его accuracy/ECE и есть оценка без эталонной генерации.
- `context/03_agent_evaluation_branching.py` — оценка по
  наблюдаемым фактам для агентских прогонов; `01` здесь — тот же вопрос, но для
  качества ответа модели.
